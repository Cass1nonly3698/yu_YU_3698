RP-Hub 完整本地加密备份与恢复 — 本地验收候选
基线：2e42cecb2ecda2988de9f76dea5c30982a85fa94
本轮仅本地开发与合成测试；未发布、未迁移真实资料。

功能与边界

设置 → 备份与转移 → 完整备份与恢复 · 本地加密。
原有上传/下载普通备份继续保留，cloud-backup.js 未修改。
工具是同一 RP-Hub 下的完整备份页面，不是第二个网站或 PWA。它不加载聊天应用、不申请通知权限、不调用模型/向量/生图 API、不使用网络上传；CSP 的 connect-src 为 none。

一个 .rphub 文件包含角色对象、主/支线原文、经典与二次压缩记忆及嵌套来源、原始量化向量/其他支持的向量编码值、世界书、预设、正则、模型配置与 Key、用户人设、UI 模板、界面偏好、小纸条及互动元数据。沿用原 uuid、scope、消息 ID、记忆编号和来源 ID，不重新总结、不计算 embedding。

同一密码通过 Web Crypto PBKDF2-SHA256（600,000 次）派生 AES-256-GCM 密钥；每次导出使用新的随机盐和 IV。格式/版本/用途等头信息纳入认证，解密后再核对完整资料摘要。没有密码找回入口，不存明文密码或密钥日志。加密文件仍应妥善保管，这不是第三方安全审计认证。

RPHubDB/store 与旧库有效回退值按白名单只读采集，主库优先。对象标签编码支持向量字节、日期、undefined 等，不会用字符串替代类型或重建身份。未知键、未知格式、重复 ID、缺失角色关联或记忆来源关系会停止操作，不默默跳过。

localStorage 迁移白名单：rphub-appearance、rp_hub_visual_cottage_v1、rp_hub_proactive_config_v1。匿名在线 ID、云备份取件码、更新提示已读标记等环境元数据不搬迁。

目标恢复采用“按备份恢复对应资料并保留备份外目标资料”的方式。目标独有角色、分支和小纸条保留；备份涉及的全局设置/预设/模板集合在确认冲突后以备份集合为准。同 ID 不同内容列入冲突；相同记录不重复追加。
如果恢复了不同原文，而备份不含该分支摘要，预检会明确列出需要移除的不匹配目标摘要；不会把旧摘要挂在新原文上。对已有源数据异常不自动修复。

推送身份

工具从不打开 HaishenPushTestV3，不读取/写入 device/backend，不注册/注销 SW，不调用 PushManager 或通知权限 API，不改 manifest、Worker、D1 或 Secrets。PWA 原推送身份留在原地，Safari 的推送身份不进入文件。
真实设备凭证可能自然过期；“未被工具改变”不等于“始终有效”，后续独立验收，不为迁移擅自重新配对。

受控恢复

1. 先解密、版本/来源/结构核对及存储容量预检，展示备份时间、资料数量和冲突。
2. 用户明确勾选并确认，重新检查目标是否在预检后变化；变化则重新预检。
3. 写入前，用同一密码保存含目标原值及恢复计划的本地加密回退记录。
4. 持久化恢复标记，再用主库事务提交，随后恢复白名单 localStorage，最后读取全部资料核对。
5. 写入失败自动回退并核对；如果回退自身也失败，保留恢复标记及加密记录。普通主线初始化被挡在恢复入口之外。
6. 浏览器关闭/进程中断后，重新打开会进入恢复页，用当时密码选择继续或回退，不依赖重新请求模型。

IndexedDB 与 localStorage 不是同一个事务。工具使用加密日志和恢复入口协调，并对关键写事务请求 strict 持久性。它不能承诺设备损坏、系统清除网站数据或密码遗失后仍能恢复，因此原文件和 Safari 原资料都应继续保留。

跨窗口采用 Web Locks。其他新版新家窗口占锁时操作会拒绝；旧版本窗口无法参与这一锁协议，实际使用前必须关闭全部旧窗口后从原 PWA 图标重开。不要在恢复过程中升级应用、清理网站数据或删除主屏幕图标。

实际 Safari → PWA 步骤（业主验收并同意发布后才执行）

1. Safari 结束聊天、记忆任务及待补画任务，确认最后一轮已保存，另存未发送草稿。
2. 关闭其他新家窗口，进入完整备份入口；按钮会先保存当前应用资料，再进入隔离的工具页。生成一份加密文件，在 iOS“文件”等位置确认确实保存成功，密码分开保管。
3. Safari 原资料保留，不清空、不做恢复覆盖。必要时另存一份加密文件副本。
4. 从原有“海神来信”主屏幕图标打开 PWA，通过现有“回小家”进入设置。不要重新安装，不重新配对。
5. 如 PWA 已有真实主线资料，先在 PWA 导出其完整备份作长期保险，再进行恢复。内部回退记录用于本次失败恢复，成功验证后会清理，不替代长期目标备份。
6. 选 Safari 导出的同一个 .rphub 文件，输入密码，检查备份时间、角色/分支/原文/记忆/向量/小纸条数量与冲突。预检本身不写业务资料。
7. 确认后受控恢复；若中断，用同一密码继续或回退。不要用清库、重装或重新配对来处理恢复问题。
8. 验证通过后回到主线，核对角色 UUID、首尾及中段原文、记忆编号/来源、向量及模型配置、世界书/预设开关、UI 模板、字号/背景、小纸条和重开后的持久化。
9. 核对推送设备 ID/后台/订阅指纹是否仍一致（不显示令牌），之后再按获准的真机方案验证通知。
10. 确认后只在 PWA 日常聊天，Safari 继续保留原始资料。2.0 云端同步、自动调度和文字面板未在本轮开发。

正常主线仍有原来的联网行为，如用量、更新、外部图片及可能的补画。备份工具的网络隔离仅作用于工具页面；返回正常主线前应核查是否有待处理外部任务。本轮所有浏览器网络均被本地拦截，没有真实 API 请求。

限制与尚需验收

• 本版上限为 128 MiB 的标签编码解密数据，文件约有额外加密/编码开销。超限明确停止，不截断。不是原云备份 1GB 能力的替代承诺。
• Web Crypto 加解密使用内存整块处理，手机峰值内存和大文件耗时尚未在 iPhone 上验证；容量估算是预检提示，最终写入仍可能因配额回退。
• 需要 HTTPS、安全可用的 IndexedDB/localStorage、indexedDB.databases 与 Web Locks。浏览器能力不足时拒绝操作；普通聊天仍保留原有能力。
• 实际 Safari/PWA 数据规模、旧库残留、异常来源关系及其他未知格式未读取。遇到这些情况会停止，须先核查，不能用重新生成记忆绕过去。
• 原应用启动仍会同步内置预设和规范化部分设置；本轮没有改这套规则。自定义条目与原始值保留，但同名内置自改内容及启动后实际效果仍需对照源端验收。
• API Key 只在加密文件/本地加密回退记录中迁移。本机正常应用仍按原方式使用其本地配置；本工具不把它改造成服务端 Key 系统。
• 外链图片只保存原链接，过期外链不会自动变成永久文件；内嵌附件随记录保留。未发送草稿和未持久化运行状态不属于完整文件。
• 北京时间 Userscript 未修改；Safari 扩展在 PWA 的可用性保留为后续真机验收。若不支持，再取得原脚本后设计原生接入。
• 密码遗失会同时影响加密备份及中断回退记录的解密。不要删除源数据来腾空间，也不要在未完成恢复时清除浏览器存储。
